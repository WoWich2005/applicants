# Правила оформления РПЗ — БНТУ 2025

Полные требования к оформлению расчётно-пояснительной записки дипломного проекта по специальности 1-40 01 01 «Программное обеспечение информационных технологий», кафедра ПОИСиТ.

**Источники:**
- Методичка «Дипломное проектирование» БНТУ 2025 (кафедра ПОИСиТ) — `reference/Методичка по ДП.pdf`
- Инструкция БНТУ №105 от 27.01.2014
- Замечания нормоконтроля — `reference/Сообщения от нормоконтроля.txt`
- ГОСТы: 2.105-95, 2.104-2006, 2.605, 7.9, 7.1-2003, 7.82-2001

---

## Общие параметры страницы (п. 4.1.1)

- Шрифт: **Times New Roman 14 пт**
- Межстрочный интервал: **18 пт**, точно
- Выравнивание текста: **по ширине**
- Поля: левое 30 мм, правое 15 мм, верх 20 мм, низ 20 мм
- Абзацный отступ: **1,25 см**, одинаковый по всему тексту
- Интервал перед и после абзаца: **0 пт**
- Объём РПЗ (без списка, графики, приложений): **не более 80 страниц**

---

## Структура РПЗ (п. 3.2) — строго в этом порядке

1. Титульный лист — включается в нумерацию, **номер не ставится**
2. Задание (формат А4, печатается с 2 сторон, с зеркальными полями) — как **1 страница**, **номер не ставится**
3. Реферат — включается в нумерацию, **номер не ставится**
4. Ведомость объёма — включается в нумерацию, **номер не ставится**
5. Оглавление — **номер ставится со 2-й страницы оглавления** (это страница 6)
6. Перечень условных обозначений (при необходимости)
7. Введение (2–5 страниц)
8. Обзор предметной области (аналитический раздел)
9. Основная часть: разработка ПО, экономический раздел, охрана труда (65–80% объёма)
10. Заключение (1–3 страницы)
11. Список использованных источников
12. Графический материал (10–15 листов, оформляется как приложение после списка литературы)
13. Приложения

## Нумерация страниц (п. 4.1.3–4.1.4)

- Арабские цифры, **в правом верхнем углу**, без точки
- Сквозная, включая список литературы, графику, приложения
- **Не ставятся** на: титульном листе, задании, ведомости, реферате, **1-й странице оглавления**
- Нумерация начинается с **6-й страницы** — это 2-я страница оглавления
- Если оглавление занимает 1 страницу — введение начинается с 6-й страницы
- В колонтитулах после номера страницы — **нет пустой строки**

---

## Оглавление (п. 3.8 + нормоконтроль)

- Помещается сразу после ведомости объёма
- Слово **ОГЛАВЛЕНИЕ** — прописными буквами **по центру** страницы, полужирный
- Включает заголовки всех частей РПЗ, в том числе ведомость объёма и подразделов
- **Без абзацного отступа** для строк разделов; подразделы — небольшое смещение вправо (только визуальное, не абзацный отступ)
- Шрифт строк: **14 пт** (не меньше)
- Номера страниц: **по правому краю** с точками-заполнителями
- Многострочный заголовок в оглавлении: продолжение строки начинается **под цифрой номера** (не под первой буквой) — ГОСТ 2.105

## Заголовки разделов и подразделов (п. 4.1.2, 4.1.5, 4.1.7–4.1.9)

### Ненумерованные разделы (ВВЕДЕНИЕ, ЗАКЛЮЧЕНИЕ, ОГЛАВЛЕНИЕ, СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ, ПЕРЕЧЕНЬ УСЛОВНЫХ ОБОЗНАЧЕНИЙ)

- По **центру** строки
- **Прописные** буквы, **полужирный** 14 пт
- **Без точки** в конце
- **Без абзацного отступа**
- Интервал перед и после: **0 пт**
- После заголовка — **1 пустая строка** (18 пт)

### Нумерованные разделы (п. 4.1.7)

- Начинаются с **новой страницы**
- Нумеруются арабскими цифрами: «1 ОБЗОР ЛИТЕРАТУРЫ»
- **Прописные** буквы, **полужирный** 14 пт
- С **абзацного отступа** (1,25 см)
- **Без точки** в конце
- Интервал перед: **0 пт**; после: **18 пт** (1 свободная строка)

### Подразделы (п. 4.1.2 + 4.1.8)

- С **абзацного отступа**
- Строчные буквы с первой прописной, **полужирный 13 пт** (методичка 2026 п. 4.1.2)
- **Без точки** в конце
- Нумерация в пределах раздела: «1.1 Сведения из истории»
- Интервал перед: **18 пт** (1 свободная строка); после: **18 пт**

### Пункты (subsubsection)

- С **абзацного отступа**
- Строчные буквы с первой прописной, **полужирный 13 пт** (методичка явно не задаёт размер для пунктов; используем 13 пт = размер подраздела, иерархия читается по номеру)
- **Без точки** в конце
- Нумерация в пределах подраздела: «1.1.1 ...»
- Интервал перед: **18 пт**; после: **18 пт**

### Многострочные заголовки (п. 4.1.9 + нормоконтроль)

- Переносы слов в заголовках **не допускаются**
- Продолжение строки выравнивается **по первой цифре номера** (ГОСТ 2.105)

### Расстояния (п. 4.1.10)

- Между текстом и следующим заголовком раздела/подраздела: **1 свободная строка**
- Между заголовком раздела и подраздела: **1 свободная строка**

## Иллюстрации (п. 4.1.11–4.1.13)

- Располагаются **после текста** (где упоминаются) или на следующей странице
- По **центру** листа
- Нумерация в пределах раздела: «Рисунок 1.1 — Диаграмма вариантов использования»
- Подпись — **под рисунком**, **по центру**, **без точки** в конце
- В приложениях: «Рисунок А.3»
- Расстояние: текст ↔ рисунок ↔ подпись ↔ текст — **1 свободная строка** каждый интервал
- Интервал перед подписью: **0 пт**, после: **0 пт**
- Рисунки не должны выходить за поля
- Рисунки должны быть **читаемыми**, по возможности увеличивать в ширину

### Стилевая конвенция БНТУ ПОИСиТ (по образцам защищённых дипломов)

Методичка прямо не запрещает цвет, но устоявшаяся практика кафедры (видна в образцах в `reference/Диплом Костин/`) такова:

- **Строго чёрно-белые** диаграммы — без цветных заливок, синих/зелёных/жёлтых блоков
- Тонкие чёрные линии, белые заливки, чёрный текст
- Никаких UML-стилизаций вроде `«person»`, `«container»`, цветных C4-блоков
- Шрифт в подписях — Times New Roman (как в основном тексте) для единообразия

### Блок-схемы алгоритмов (ГОСТ 19.701-90)

Для блок-схем алгоритмов кафедра ожидает строгого соответствия ГОСТ 19.701-90:

| Элемент | Форма |
|---|---|
| Процесс/действие | **прямой** прямоугольник (не rounded!) |
| Условие/решение | ромб |
| Начало/конец | овал-«пилюля» с подписью «Начало»/«Конец» |
| Ввод/вывод данных | параллелограмм |
| Подготовка | шестиугольник |
| Стрелки | прямые с одиночной стрелкой |
| Подписи ветвей условия | «Да»/«Нет» возле выходов ромба |

PlantUML по умолчанию рендерит activity-диаграммы в UML-стиле (rounded rectangles + чёрные круги для start/stop) — это **не ГОСТ**. Для строгого соответствия использовать TikZ с пакетом `flowchart` либо draw.io с палитрой «Flowchart shapes».

## Таблицы (п. 4.1.14–4.1.19)

- По **центру**, после текста
- Нумерация в пределах раздела
- Заголовок **над** таблицей, **по левому краю**: «Таблица 6.1 — Технико-экономические показатели»
- **Без точки** после названия
- Ширина линий границы: **0,5 пт**
- В таблицах допускается уменьшать шрифт и межстрочный интервал
- При переносе: «Продолжение таблицы 6.1» — над продолжением, по левому краю
- Расстояние: текст ↔ подпись ↔ таблица ↔ текст — **1 свободная строка**
- В приложениях: «Таблица А.3»

### Размещение нескольких таблиц подряд (п. 4.1.14, толкование)

Методичка требует размещать таблицу «непосредственно после текста, в котором она упоминается впервые». Это толкуется нормоконтролем строго:

- **Перед каждой таблицей** должно быть отдельное вводное предложение со ссылкой именно на неё.
- **Нельзя** одну общую фразу «таблицы~\ref{...}, \ref{...}, \ref{...}» с тремя ссылками подряд, после которой идут три таблицы один за одним.
- Если несколько таблиц логически связаны — между ними должен быть хотя бы короткий поясняющий абзац.

### Малые таблицы и разрывы страниц (практическое замечание)

`longtblr` (tabularray) поддерживает разрыв таблиц на нескольких страницах, но **для маленьких таблиц** (2–5 строк) LaTeX предпочитает не разрывать и переносит их целиком на следующую страницу. Это может оставить большую пустоту в конце текущей страницы (нарушает «3–4 строки максимум» — см. нормоконтроль).

Лечится одним из способов:
- **Перестановкой**: вынести таблицу в конец подраздела, чтобы после неё сразу шёл новый подраздел (тогда отрыв безопасен).
- **Уплотнением текста выше**: сократить вводные абзацы, освободив место под таблицу на текущей странице.
- **Расширением текста выше**: добавить содержательный текст, чтобы таблица «съехала» ровно вниз страницы.

## Перечисления (п. 4.1.20–4.1.21)

- С **абзацного отступа**, строчными буквами
- Нумерованный: `1)` ... разделяются `;`, последний — `.`
- Маркированный: тире `–` (именно тире, не дефис)
- Каждый пункт — отдельный абзац

## Оформление чисел (ГОСТ 8.417-2002)

Методичка прямо правил для чисел не задаёт и отсылает к общим стандартам. Применяется ГОСТ 8.417-2002 «Единицы величин»:

### Десятичный разделитель

- **Запятая**, не точка: `12,5`, не `12.5`
- В math-режиме `$...$` запятая оборачивается в `{,}` чтобы LaTeX не вставлял лишний пробел: `$18\,855{,}90$`. В обычном тексте — обычная запятая

### Разделитель разрядов

- Применяется только к числам с **5 и более цифр**
- **4-значные** числа (1000–9999) пишутся **слитно**, без разделителя: `2400`, `3500`, `7046`
- В обычном тексте/таблицах разделитель — **неразрывный пробел** через `~`: `47~912,85`, `12~570,60`
- В math-режиме — **тонкий пробел** `\,`: `47\,912{,}85`, `42\,978`
- Использовать единый стиль в одном контексте; не смешивать `~` и `\,` в одной формуле

### Числа с единицами измерения

- Через **неразрывный пробел** `~`: `4{,}5~м²`, `120~ккал/ч`, `15~кВ/м`, `300--500~люкс`, `5~Гц--2~кГц`
- Степень в единицах — `\textsuperscript{2}`: `м\textsuperscript{2}`, `Вт/м\textsuperscript{2}`
- Знак `/` в **единицах** (м/с, ккал/ч, Вт/м²) допустим — это часть обозначения единицы по СИ, а не математический оператор
- Знак `/` в **формулах** — только дробью

### Диапазоны чисел

- Через короткое тире без пробелов: `300--500`, `5--7~мА`, `22--24` (выводит `–` в PDF)
- Если оба числа имеют единицу — единицу указывают один раз, после второго числа: `5~Гц--2~кГц`, но не `5~Гц--2~Гц`

### Денежные суммы

- Сокращение «руб.» (не «р.»), всегда с точкой: `7046~руб.`, `17~300~руб./год`
- В шапках таблиц: «Сумма, руб.», «Ставка, руб./ч»

### Числа в начале предложения

- Если число начинает предложение, его пишут **прописью**: «Двадцать абитуриентов…», не «20 абитуриентов…»

## Даты

- Формат: `ДД.ММ.ГГГГ`
- После даты — `~г.` через неразрывный пробел: `от 25.01.2021~г.`, `от 14.04.2021~г. №~25`
- Номер документа — через неразрывный пробел: `№~37`, `№~829`
- В тексте диплома — год 2026 (см. memory `diploma_year_2026.md`)
- В списке источников для электронных ресурсов: `Дата доступа: ДД.ММ.ГГГГ` (с пробелом, без `~г.`)

## Формулы (п. 4.1.22–4.1.26)

- Выделяются в **отдельную строку по центру**
- Выше и ниже — **1 свободная строка**
- Нумерация: арабскими цифрами в круглых скобках в **крайнем правом положении** строки, в пределах раздела: (4.2)
- Заканчиваются знаком препинания: запятая (если есть расшифровка), точка с запятой (перечисление), точка (конец)
- **Вычисления (численные подстановки) заканчиваются точкой** (п. 4.1.24)
- Латинские буквы — **курсив**; русские и греческие — **прямой шрифт** (п. 4.1.23)
- **Локальная конвенция кафедры ПОИСиТ ФИТР**: внутри блоков `explanationx` (расшифровка «где X — …») латинские переменные оформляются **прямыми** (через `\mathrm{...}`), а кириллица — всегда прямая (через `\rv{...}` = `\text{...}`). В самой формуле латиница остаётся курсивной. Методичка п. 4.1.23 это явно не требует, но устоявшаяся практика кафедры именно такова (подтверждено нормоконтролем). См. memory `diploma_latin_letters_in_formulas.md`.
- Расшифровка: начинается со слова «где» **без двоеточия, с абзаца** (1,25 см); по примеру из методички **все последующие строки выравниваются с тем же абзацным отступом** (формулировка «обычное выравнивание» из п. 4.1.26 = «как обычные абзацы текста», то есть с тем же отступом 1,25 см, а не margin 0). Переменные через `;` кроме последней — `.`
- Знак деления — **только дробью** (не `/`)
- Без абзацного отступа у формул; интервалы перед/после: **0 пт**
- **Промежуточные подстановки** — без номера (норм-контроль); единицы измерения после результата — в круглых скобках через пробел: `= 16 300 (руб./год).`

### Математический шрифт

Без явной настройки XeLaTeX использует Computer Modern для math-режима, и цифры/латиница в формулах визуально отличаются от Times в тексте. В проекте применён гибридный подход:

```latex
\usepackage{unicode-math}
\setmathfont{texgyretermes-math.otf}              % Times-клон от GUST: символы, греческие, дробь
\setmathfont{Times New Roman}[range=up/num]       % подмена цифр на реальный Times
```

Таким образом цифры в формулах и цифры в обычном тексте берутся из одного шрифт-файла (Times New Roman), а математические символы (∑, ∫, ≈, ≥, греческие, дробная черта) — из совместимого с Times TG Termes Math.

## Список использованных источников (п. 4.1.27–4.1.28)

- Заголовок: СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ (прописные, по центру, полужирный)
- По порядку появления в тексте или по алфавиту
- Каждый пункт — **без абзацного отступа**, выравнивание по ширине

- По ГОСТ 7.1-2003; для электронных ресурсов — режим и дата доступа (нормоконтроль п. 13)

## Приложения (п. 4.1.29)

- Начинаются с **новой страницы**
- Вверху по центру: **ПРИЛОЖЕНИЕ А** (прописными)
- Ниже по центру: заголовок строчными с первой прописной
- Буквы русского/белорусского алфавита начиная с А, исключая Е, З, Й, О, Ч, Ь, Ы, Ъ
- Листинги до 1 страницы — оформляются **как рисунок** в тексте; свыше 1 страницы — **как приложение**

## Реферат (п. 3.7 + нормоконтроль)

- Не более 1 страницы
- 5–6 ключевых слов в именительном падеже, прописными через запятые
- Обязательные предложения: объект, цель и задачи исследования, что сделано, результат, научная новизна
- По ГОСТ 7.9
- Количество страниц/рисунков/таблиц — только до заключения включительно
- Отсчёт страниц с титульного листа; последняя страница заключения = количество страниц диплома

## Инструменты для иллюстраций

В проекте используется подход «диаграмма как код» — все исходники текстовые, версионируются в git, рендерятся автоматически.

### PlantUML

Для UML-диаграмм (use case, sequence, class, component, ER) и архитектурных схем.

- Установка: `brew install plantuml`
- Исходники: `diploma/diagrams/*.puml`
- Сборка: `./build-diagrams.sh` (генерит PNG в `diploma/images/`)
- Сборка одного файла: `./build-diagrams.sh имя-без-расширения`

Обязательные `skinparam` для соответствия конвенции БНТУ:

```
skinparam DefaultFontName "Times New Roman"
skinparam DefaultFontSize 14
skinparam Monochrome true
skinparam Shadowing false
skinparam BackgroundColor #FFFFFF
skinparam ArrowColor #000000
```

### TikZ для блок-схем

PlantUML activity-диаграммы **не соответствуют ГОСТ 19.701-90** (rounded rectangles вместо прямоугольников, чёрный круг вместо овала «Конец»). Для строгого соответствия — использовать TikZ inline в `.tex`:

```latex
\usetikzlibrary{shapes.geometric, arrows.meta}
% startstop, process, decision, io shapes
```

Альтернатива — draw.io с палитрой «Flowchart shapes» по ISO/ГОСТ.

### pgfplots для графиков

Для числовых графиков (например, ЧДД нарастающим итогом) — pgfplots прямо в `.tex`. Шрифт согласован с основным текстом (Times через unicode-math), не нужно экспортировать из Excel.

### Скриншоты пользовательского интерфейса

- macOS `Cmd+Shift+4` для ручных скриншотов в `images/*.png`
- Для автоматизации — Playwright (поднимает app, проходит сценарий, делает PNG)

### Граничный вопрос — что в каком формате

| Тип | Инструмент |
|---|---|
| Use case, sequence, class, component, ER | PlantUML |
| Архитектура (контейнерная) | PlantUML (обычная component, **не C4-стиль** с цветом) |
| Блок-схема алгоритма по ГОСТ | TikZ или draw.io |
| Графики чисел | pgfplots |
| Скриншоты UI | macOS Cmd+Shift+4 или Playwright |
| Структура каталогов проекта | моноширинный листинг в `.tex`, не картинка |

## Замечания нормоконтроля (сводка из reference/Сообщения от нормоконтроля.txt)

- Шрифт оглавления: 14 пт, номера страниц по правому краю
- Во введении: **никаких жирных и курсивных** шрифтов
- Для всех центрированных заголовков: **нет абзацного отступа**, интервалы перед/после = 0
- Для всех рисунков: интервалы перед/после = 0
- Для подписей к рисункам: нет абзацного отступа, интервалы = 0
- Для формул: нет абзацного отступа, интервалы = 0
- В колонтитулах после номера страницы: **нет пустой строки**
- Рисунки — читаемые, увеличивать в ширину; не выходить за поля
- Избегать висячих строк и пустого места в конце страниц (максимум 3–4 пустые строки снизу)
- Лист задания — зеркальные поля, печатается с двух сторон
- Лист ведомости объёма: поле слева 2 см, остальные 0,5 см
- В тексте **обязательно** должны быть ссылки на литературу в формате `[N]`
- Знака деления `/` в формулах быть не должно — только дробью
- В списке литературы для электронных ресурсов обязательно указывать режим и дату доступа

### Локальные конвенции кафедры ПОИСиТ ФИТР (не в письменной методичке)

Выявлены в процессе работы и подтверждены нормоконтролем:

- Латинские переменные внутри расшифровок «где...» — **прямые** (через `\mathrm{}`), хотя п. 4.1.23 формально требует курсива только для формул. См. memory `diploma_latin_letters_in_formulas.md`.
- Иллюстрации — **строго чёрно-белые** (видно по образцу диплома Костина в `reference/`).
- Блок-схемы алгоритмов — **строго по ГОСТ 19.701-90** (прямые прямоугольники, овалы «Начало»/«Конец»).
- Между двумя таблицами должен быть хотя бы короткий поясняющий текст — нельзя одной фразой ссылаться на несколько таблиц подряд.
